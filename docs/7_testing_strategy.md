# Стратегія тестування

1. Мета та обсяг тестування:
- перевірка правильності розрахунків моделі Project (залишок годин, дні до дедлайну, денна норма часу);
- перевірка крайових ситуацій (нульові значення, прострочені дедлайни, перевищення відпрацьованих годин);
- інтеграційна перевірка збереження та завантаження списку проектів у JSON-файл;
- модульне тестування сервісу планування розкладу на 7 днів після рефакторингу.

2. Інструменти та середовище:
- фреймворк модульного тестування xUnit (проект MindPace.Tests);
- запуск тестів через Test Explorer у Visual Studio або командою dotnet test.

3. Види тестів у проекті:
- модульні тести (ProjectCalculationTests, ScheduleCalculatorTests) — ізольована перевірка методів без прив'язки до інтерфейсу WPF;
- тести граничних значень (EdgeCaseTests) — перевірка поведінки формул на межі допустимих даних;
- інтеграційні тести (StorageIntegrationTests) — перевірка серіалізації та читання даних із файлової системи.
